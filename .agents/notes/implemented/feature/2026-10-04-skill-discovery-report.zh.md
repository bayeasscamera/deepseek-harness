# Agent Note: 未被发现的 skill 会说明原因

Status: implemented

[English](2026-10-04-skill-discovery-report.md) | 中文

## Problem

本地 skill 发现只读取一层：`<root>/<name>/SKILL.md` 或 `<root>/<name>.md`。根目录中的其他内容都无声地等于不存在。一个装着 skill 集合的文件夹——所有公开目录集发布的都是这种形状——不会贡献任何 skill、不产生日志行、也不出现在目录中；而 Skills 标签页自己的提示恰恰在邀请这种放置方式（「将包含 SKILL.md 的文件夹放入其中即可安装 Skill」），它的导入操作本可以把同一个文件夹正确安装。

代价在一台机器上可以直接测量：`~/.dsh/skills` 中有四个这样的文件夹，合计携带 670 个 `SKILL.md`（其中一个克隆的示例仓库占 636 个），而目录只显示 45 个 skill，且没有任何东西解释这个差距。提供方 README 记录了「一层深度」规则与模型侧的缺口（「模型目录不会收到逐 skill 诊断，无法区分缺失的 skill 与无效的 skill」），但没有任何东西告诉操作者——而操作者是唯一能修复它的人。

## Decision

提供方现在可以在候选项之外报告 **skip**，面向用户的界面会渲染它们。`SkillProviderObservation.skipped?: readonly SkillDiscoverySkip[]` 承载 `{ path, reason, nested?, truncated? }`，其中 `reason` 为 `nested-skills`、`invalid-frontmatter`、`missing-name`、`invalid-name` 或 `unreadable`；`SkillCatalogSnapshot.skipped` 是合并后的列表，按「层级、再按提供方」顺序，每个路径一条发现。

三条规则决定什么会被报告：

- **只有真正含有 skill 的文件夹才算发现。** 其下没有 `SKILL.md` 的文件夹（资源目录、`node_modules`）不报告任何内容；含有有界数量嵌套清单的文件夹报告 `nested-skills` 及该数量。
- **数量等于一次导入会安装的数量。** 该遍历复用导入扫描的深度，并在清单上限与目录预算处停止，报告 `truncated: true` 而不是遍历无界树，因此「导入它」正是报告本身暗示的修复方式。上限约束的是工作量，而不只是输出。
- **只有被确认的缺失才算缺失。** bundle 文件夹是否有清单由存在性检查决定，而不是从读取失败反推；只有等同于 `ENOENT` 的失败才回答「缺失」；存在但无法读取的路径会进入读取路径，因此瞬时 I/O 失败仍会把观测标记为不完整并保留最后一份可用目录，而不是悄悄变成「这里没有 skill」。在列出与读取之间消失的清单属于扫描竞态，不对任何人报告。

该诊断绝不进入模型目录：模型无法据此行动，而目录是路由界面，不是状态页。设置控制器把它与目录放在同一个 wire 值上（`SkillListValue { skills, skipped }`），Skills 标签页把它渲染在已找到的列表上方——每个条目一行，带原因，最多列出十条并附一条余量行。

格式错误的 skip 与格式错误的候选项一样会让观测失败：未指明路径或理由未知的诊断信息属于提供方缺陷，读一半比整体拒绝更糟。

## Alternatives considered

**就地发现插件布局**（`<plugin>/skills/<name>/SKILL.md`）。多一层就能让克隆来的集合无需导入即可工作，这也是用户把 skill 仓库克隆进根目录时的预期。它因两点落选：仅这台机器上的示例仓库就会加入 636 条操作者从未选择的目录条目（约 4 万 token）；而导入流程本就存在、本就能正确展平选中的文件夹，并把选择权留给用户。问题在于沉默，而不是深度。

**只在主机日志中警告。** 成本最低，而且提供方已经在为格式错误的清单记录日志。它落选是因为日志不是提问的地方：操作者看的是 Skills 标签页，而主机日志行回答的是没有人正在读的问题。

**报告每一个没有清单的文件夹。** 不需要有界扫描，没有数量，也没有漏报风险。它落选是因为那会报告普通的资源目录，而大部分是噪音的报告会不再被人阅读——这条提示必须意味着「这一个确实是 skill 集合」。

**把诊断放进模型目录。** 那样模型就能告诉用户某个 skill 为何缺失。它落选是因为目录会注入每一步的上下文：一台有四个被跳过文件夹的机器会为这段文字在每次请求中付费，而这个事实只有操作者能处理。

## Consequences

放进 skill 根目录的文件夹现在要么产出 skill，要么给出一条明确原因，从而关闭了 README 此前记为「限制」而非「决定」的缺口。提供方只在未命中的路径上拥有一段有界诊断遍历（深度、清单数、目录数），注册表则多携带一个字段穿过缓存——skip 与它们所描述的目录一起缓存，因此第二次读取不会重新遍历任何东西。

仍有两项限制，均记录在 README 中：数量是有界的，因此非常大的集合会报告 `truncated` 与一个下限而非精确数字；彻底发现失败的提供方除了注册表自己的日志行之外不会贡献任何发现，因为被拒绝的提供方没有可据以报告的观测。
