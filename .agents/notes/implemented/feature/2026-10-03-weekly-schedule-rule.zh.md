# Agent Note: 带显式时区的每周调度规则

Status: implemented

[English](2026-10-03-weekly-schedule-rule.md) | 中文

## Problem

Schedule 此前只能按固定间隔重复。这一版自己的例子——「每周一早上 9 点根据 CSV 重新生成这份报告」——需要的是一条同时给出星期几、本地时间与时区的规则；而已交付范围把日历式重复记为未来的产品边界，而不是假装固定间隔已经覆盖它：`every_seconds` 与创建锚点对齐，因此用它拼出的规则每年会漂移两小时，而且根本无法表达「周一」。

## Decision

`schedule` 增加一种 `weekly` 记录: `{ kind: 'weekly', prompt, weekday, time, timeZone, scheduledAt }`。其中 `weekday` 是 ISO 星期几（1 为周一），`time` 是不含秒的本地 `HH:MM`，`timeZone` 是规范化的 IANA Area/Location 时区，`scheduledAt` 仍是尚未派发的最早发生时刻。`schedule_create` 在 `after_seconds`、`at` 与 `every_seconds` 之外接受第四个选择器 `weekly`；工具在写入任何内容之前拒绝 1–7 之外的星期几或不是 `HH:MM` 的时间，记录构建器则拒绝本运行时无法解析的时区。

发生时刻在记录自己的时区中解析，而规则保持的是本地墙钟：同一个 `09:00` 在夏令时切换前后仍然是 `09:00`，其 UTC 瞬间随偏移变化而移动。两个边界是被明确决定的，而不是听凭运气。春季跳时把所声明时刻整段跳过时——例如从 `02:00` 直接跳到 `03:00` 的时区里的 `02:30`——提醒在缺口之后的第一个瞬间触发，因为「时钟越过目标时到达」胜过「永远不到达」；秋季重叠使该时刻出现两次时，取两个瞬间中较早的一个，这也正是既有 `at` 解析对本地时间的做法。在日历末端，规则报告它最后一个可表示的发生时刻且不再给出下一目标，与固定间隔完全一致。

客户端目录会把规则说出来，而不是贴错标签：每周记录用文档语言的 `Intl.DateTimeFormat` 渲染星期几，并附上记录中保存的本地时间，因此该行显示「Every Monday at 09:00」，而不再落到单次标签。

运行时的批量路径是被推广而不是被复制的：`EveryDue` 变成 `RecurringDue`，决策种类 `every` 变成 `recurring`，framing 渲染器 `renderEveryReminderBatchFraming` 变成 `renderRecurringReminderBatchFraming`，于是一个逾期批次按「目标时间、再按创建顺序」同时携带固定间隔与每周提醒。两种记录的追赶都只取最新一次，与固定间隔此前的行为一致。

**不提升会话格式版本。** 新增记录种类属于 payload 增加，而版本机制自身的规则是 v2「对普通的事件词汇与 payload 增加保持物理编解码器中立」——版本整数是为结构性变化（header 形状、信封、核心事件语义、surface 机制）而存在的。因此这次改动不带迁移边，旧构建遇到 `weekly` 记录时会拒绝该记录而不是误读它，这正是「读取方不认识的 payload 词汇」的既定行为。

## Alternatives considered

**Cron 表达式。** 一个字段就能表达人们可能想要的所有规则，模型也已经熟悉这套语法。它输在：为一个人设只需要「一个星期几加一个时间」的产品面，去解析、校验、记录并在拒绝信息里解释一整门语言；而且 Cron 字符串本身不带时区，时区仍得另附。

**用 `every_seconds` 的整周倍数。** 不需要新记录种类，也不需要新算术。它输在正确性：固定间隔与创建锚点对齐，因此用它拼出的每周规则保持其 UTC 瞬间，在每次夏令时切换时漂移一小时，而且根本无法指名星期几。

**存解析后的 UTC 偏移而不是时区。** 发生时刻的算术会更简单，记录也更小。它输在这是同一个漂移的另一种写法：冬天捕获的偏移在夏天是错的，而要重新解析它又需要那个被丢掉的时区。

**提升会话格式版本并加一条迁移边。** 作为「拿不准就提升」的保守解读是站得住的。它输在机制笔记已经回答了这种情况：payload 增加正是 v2 编解码器明确保持中立的对象，而一条恒等迁移边只是相邻目录机制必须永久背负的仪式。

## Consequences

提醒现在可以说「每周一 09:00，Europe/Paris」，并在夏令时切换前后守住这句话——这正是这一版所要求的。代价是给一个本就拥有时间算术的包再加一层：每周路径新增了时区投影、用于找出到期本地日期的有界七天回溯，以及上面两个夏令时裁决；它们都由测试钉住了巴黎春季跳时与秋季重叠的具体瞬间，而不是听信库本身。限制记在 README 里：一个星期几、一个本地时间、没有按月某日、没有 Cron，而且本分组仍然无法触达 cold 会话。
