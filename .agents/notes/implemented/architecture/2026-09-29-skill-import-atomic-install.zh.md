# Agent Note: 技能导入通过暂存副本与一次 rename 完成安装

Status: implemented

[English](2026-09-29-skill-import-atomic-install.md) | 中文

## 问题

`settings/importSkill` 直接把选中的文件夹复制到目标上，并把对该目标的 `stat` 当作冲突检测。三处缺陷都源自这个写法，且都不出现在成功路径里。先 `stat` 再 `cp` 是检查与使用之间的竞态：`fs.cp` 在 `recursive` 下会**合并进**已存在的目录而不是拒绝，因此两个并发导入可能把文件交错写进一个已安装的技能。复制中途失败会在用户技能目录里留下写了一半的文件夹，发现阶段会把它当作无名条目、记日志，并且此后无法再覆盖导入。导入自身还会重扫根目录，于是在安装成功之后，一次发现失败会把导入报告为失败，而技能其实已落在磁盘上。

## 决策

安装即目录发布，因此改用平台已有的发布原语：先在目标旁边写好，再 rename 过去。rename 是唯一可能撞上已存在目标的步骤，因此它的拒绝就是冲突信号，不再需要单独的存在性检查。`cp` 使用 `verbatimSymlinks`，使导入文件夹内的链接保留其书写目标，而不是被按新位置改写为相对路径。每个 controller 同时只跑一次安装：安装期间到达的调用方加入正在进行的安装，而不是与之竞态。选中的文件夹若包含用户技能目录，则在校验之前就拒绝，因为复制它会递归经过安装自己创建的暂存副本。重扫移交给调用方——它本来就有一个：标签页在导入成功后通过 `refreshSkills` 刷新。

`containsDirectory` 在比较前用 `realpath` 解析两条路径，因为选择器可能返回相对路径或同一文件夹的符号链接写法，而词法前缀比较会漏掉后者。

被接受的名称是唯一决定目标的东西，而接受契约已将其限制为 kebab-case，因此 `join` 不可能逃出用户技能目录。测试导入一个声明 `../../escaped` 的清单并断言技能目录从未被创建，这使该不变量可执行，而不是停留在口头断言。

## 考虑过的替代方案

**保留复制，只把存在性检查提前。** `recursive` 下的 `fs.cp` 会合并进已存在的目录，因此提前检查只是缩小了窗口而没有关闭它：两个导入在检查与复制之间竞态时，仍会把文件交错写进一个已安装的技能。rename 要么发布整个目录，要么什么都不发布。

**用词法前缀判断包含关系。** 选择器可能返回相对路径或同一文件夹的符号链接写法，直接比较未解析的字符串会漏掉该检查存在的理由；两侧都用 `realpath` 解析才成立。

**在导入内部刷新发现。** 那样一来，后续重扫失败时，导入会把一个确实已落盘的技能报告为失败。重扫属于调用方——它本就通过 `refreshSkills` 列举。

## 后果

被拒绝的导入不再合并进已安装的技能，也不再留下阻塞下一次尝试的文件夹。线上结果类型未变，因此标签页与 SDK 客户端无需协议改动。

宿主不再把发现刷新作为导入的副作用。`importSkill` 的文档说明调用方需通过 `refreshSkills` 观察已安装的文件夹，而标签页本就如此。

标签页现在会在卸载时清空其反馈计时器，使消息无法再对已卸载组件设置状态；同时新增渲染测试覆盖组件各状态，而不是把它们留给浏览器级测试工具。
